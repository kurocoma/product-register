1. プロジェクト概要

5つの EC プラットフォームに商品を一括登録するアプリ。既存の Excel マクロテンプレート（数式 + Power Query + VBA の 3 層構造）による CSV 生成の仕組みを、保守性の高い Python アプリに置き換える。

1.1 解決したい課題

現状の問題 解決後
Excel マクロ・Power Query・数式の 3 層構造で保守困難 Python のシンプルな関数構造で見通しが良い
既存テンプレートで Yahoo は NE 経由で登録（重複・手間） Yahoo へ直接 CSV / API で登録（Phase 2 で API 化）
セット商品が「同じ商品名・同じ画像で価格だけ違う」状態で並ぶ Yahoo の grouping-id で 1 ページに集約、数量セレクタで選択
各モールの API 仕様変更時、Excel テンプレートの修正は職人技 単体テスト + 差分検証コマンドで自動回帰検出

5. 各モール出力仕様

5.1 楽天 (normal-item.csv)

  • 形式: 楽天 RMS CSV フォーマット（最大 462 列）
  • 構造: 親行（商品レベル）＋ 子行（SKU レベル）を結合して 1 ファイル
  • 主要変換:
  • 単品 → 属性「親」、セット → 属性「子」
  • 消費税率: 入力値 10 → 出力値 0.1
  • 商品属性（単位）の 0 → null 置換
  • 商品管理番号昇順 → 属性（親先）でソート
  • 列選択: 462 項目の出力 ON/OFF フィルタ機能

5.2 ネクストエンジン (NE)

  • 形式: NE 商品マスタ CSV フォーマット
  • 出力: 単品用 CSV と セット用 CSV の 2 ファイル
  • 主要マッピング: syohin_code ← ne_code, syohin_name ← product_name, baika_tnk ← selling_price, sire_code ← maker_code

5.3 Yahoo

  • Phase 1: 85 列の正規アップロードフォーマット CSV を出力
  • セット集約: grouping-id + variation1-free-title + variation1-name で同一 JAN の単品/セットを 1 商品ページに集約
  • 画像: item-image-urls 列にセミコロン区切りで全画像 URL を出力
  • 税込価格: original-price / price ともに selling_price × (1 + tax_rate/100) の四捨五入

5.4 Shopify

  • 形式: Shopify 商品 CSV インポートフォーマット（58 列）
  • 画像複数行展開: 1 画像 = 1 行、Image Position 自動採番、1 行目のみ本体データ、2 行目以降は画像のみ
  • マーケット対応: 日本 / 国際の価格設定（Included / 日本, Price / 日本, Price / 国際 等）

6. Yahoo セット商品の集約（Phase 1 で実装）

6.1 解決した問題

入力データではセット商品は単品と「quantity と selling_price 以外まったく同じ」状態で渡される。これをそのまま Yahoo に流すと、Yahoo ストア上で「まったく同じ商品が複数並び、価格だけバラバラ」という最悪の UX になる。

従来:
  [商品A] ホワイトショコラ in 塩ちんすこう 12個入り...  ¥864
  [商品B] ホワイトショコラ in 塩ちんすこう 12個入り...  ¥4,320  ← 同じ見た目
  [商品C] ホワイトショコラ in 塩ちんすこう 12個入り...  ¥3,200  ← 同じ見た目

6.2 解決方針

Yahoo の grouping-id + variation1-* 機構を採用し、同一 JAN の単品/セットを 1 つの商品ページに集約する。

集約後:
  [商品ページ] ホワイトショコラ in 塩ちんすこう 12個入り
                数量: ○1袋 ¥864  ○5袋セット ¥4,320  ○10袋セット ¥3,200

6.3 grouping-id の生成ルール

入力 ne_code yahoo_grouping_enabled grouping-id variation1-name (unit=袋)
n019-0250-1 TRUE n019-0250 1袋
n019-0250-5 TRUE n019-0250 5袋セット
n019-0250-10 TRUE n019-0250 10袋セット
t002-2542-S01 TRUE t002-2542-S01（trim せず） 1本
x999-9999-1 FALSE （空） （空）

ロジック: ne_code 末尾が「ハイフン + 純粋な数字」のときだけ trim する。S01 のように英字を含む末尾はそのまま grouping-id とする。

運用上の注意（Phase 1 完了後）

Yahoo の CSV アップロードは「省略列がデフォルト値で上書き」される挙動の可能性があるため、既存登録商品への適用前に Yahoo テストストア (test.circus.shopping.yahooapis.jp) で動作確認が必要。Phase 1 では 新規商品登録のみで採用し、既存登録商品への上書きは Phase 2 で「上書き安全モード」を実装してから対応する。

9. WebUI（Phase 2 進行中）実装済み機能

Phase 2 として Next.js App Router + Supabase の WebUI を構築中（webui/）。変換ロジックは Phase 1 の Python から TypeScript へ移植。以下は実装・e2e 検証済み。

9.1 商品 CRUD・自動保存・3 モールプレビュー

  • 商品の一覧／編集（webui/app/(main)/products/）。編集画面は「左フォーム＋右プレビュー」の 2 ペイン構成。
  • 入力内容は debounce で自動保存（Supabase products テーブル）。
  • プレビューは 楽天 / Yahoo / Shopify の 3 タブで、フォームのライブデータを反映。

9.2 楽天ジャンル属性の自動読込

  • 「カテゴリ ID から属性を読み込む」操作で、楽天ジャンルの推奨属性（必須／任意・推奨単位）を Supabase rakuten_genre_attributes から取得しフォームへ展開。CSV では値ありの属性のみ出力。

9.3 楽天 → Yahoo カテゴリ自動入力

  • 楽天カテゴリ ID（mall_category_id）を入力（フォーカス離脱）すると、対応する Yahoo カテゴリ（yahoo_category_id / yahoo_path）を自動入力。
  • マッピングは Supabase rakuten_yahoo_category_mapping（楽天 14,367 ジャンル → Yahoo、決定的アルゴリズム＋LLM 判定のハイブリッドで約 93% 紐付け）を参照。

9.4 楽天プレビューの実レイアウト忠実描画

  • 商品画像（楽天 R-Cabinet）と説明文を、公開時と同じ形でプレビュー。
  • PC 用販売説明文（imgList）＝ R-Cabinet 画像を全幅・縦並び。
  • PC 用商品説明文 HTML（<table>・<font> 等）は iframe で隔離描画し、Tailwind の影響を受けず実ページに近い見た目で確認できる。

9.5 PC 用販売説明文（任意 HTML 入力枠）※本リリースで追加

  • 楽天「PC 用販売説明文」を任意 HTML で入力できるフィールド sale_description_pc を追加（レビューボタン・非連番画像など自由に記述可）。
  • 空欄なら従来どおり画像枚数から imgList を自動生成（後方互換）。
  • CSV 出力では「PC 用販売説明文」および「スマホ用商品説明文」の先頭に反映。
