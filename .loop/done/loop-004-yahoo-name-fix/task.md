# task.md — Yahoo 商品名(name) の HTML除去＋安全切詰

## 元依頼（ユーザー）
> loop-003(文字数整形)完了後のライブ再テストで、path/explanation は解消したが **name(it-01017) が依然失敗**。原因: 楽天 display_name が「本来の商品名 `<br>` SEOキーワード群」形式で、(1) name の HTML(`<br>`)が未除去、(2) 整形後 ~75(自前カウント)でも Yahoo はわずかに多くカウントし >75。loop-003 のテストは合成データ("あ"×100)で実データ形を見逃した。
> ユーザー選択: **キーワード保持（`<br>`除去＋75切詰・安全側上限）** を **新 eval-loop(loop-004)** で実装（実データ風テスト付き）。

確認済みの前提:
- `<br>`前の本来商品名は 19〜35全角と短く、キーワード保持でも安全側上限なら75に収まる。
- 本セッションのゴール: **name 整形のコード修正まで**。実出品(公開)はしない。修正後にライブ `e2e_migrate --commit` で実機確認（ループ外）。

## タスク種別
bugfix（Yahoo name の実データブロッカー修正。loop-003 の name 整形を実データ対応に強化）。

## 対象範囲
`webui/lib/yahoo/item-mapper.ts`（name の整形ルール）, `webui/lib/product/text-fit.ts`（HTML/改行タグ→空白・除去ヘルパ）, `webui/lib/migrate/`（必要時）。

## 非対象範囲（触らない）
`.env*`・secrets、`.claude/`・`.loop/`・`scripts/`、`package.json`/lockfile、`tsconfig`/`eslint`/`vitest`、既存テストの削除/緩和、`lib/converters/yahoo.ts`(YahooConverter)、ライブ全移行・本番公開。

## 取り組む内容（キーワード保持方針）
1. **name の HTML 除去**: `<br>`/`<br/>` は**空白に変換**（キーワード区切りを保つ）、その他タグは除去。キーワードは保持。
2. **安全側上限で切詰**: Yahoo の実カウントが全角75以内に確実に収まるよう、自前カウントで**安全マージン**を引いた実効上限（例: 全角73、または margin=2）に整形。これで Yahoo のカウント差を吸収。
3. **実データ風テスト**: 「本来の商品名 `<br>` キーワード×多数（全角/半角/記号/数字 混在）」を入力に、整形後 name に HTML が無く・実効上限以内・本来の商品名が先頭に残ることを検証（合成 "あ"×N だけにしない）。

## 互換性要件
既存テスト(226)・単品 register/yahoo・一括移行を壊さない。loop-003 の path/explanation 整形は維持。短い name(HTML無)は除去後そのまま。

## セキュリティ/運用要件
- 秘密情報を読み書き・出力しない。ライブ API は呼ばない（本ループはコード修正のみ）。

## 変更禁止事項
- 合格のためにテストを削除・スキップ・緩和しない。実装を直す。
- 受け入れ条件・criteria・eval-schema を緩めない。YahooConverter を変えない。実出品・公開を実行しない。

## 不明点と安全な仮定
- 安全マージンの具体値は generator が決めてよい（実データ名で「整形後 ≤ 実効上限」かつ「本来商品名が欠けない」を満たす範囲）。Yahoo 実カウント確認はライブ再テスト（ループ外）で担保。
- `<br>` 以外の HTML（`<b>`等）も name からは除去（plain text 化）。
